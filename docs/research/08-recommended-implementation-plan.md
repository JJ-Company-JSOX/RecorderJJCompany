## 建议实际执行批次

### 批次0：已完成审计后最小修复

A-01：新增共享纯 `projectVersion.ts`，main和renderer都只接受整数v1/v2；未来版本在授权素材和切换会话前拒绝。没有升级格式或迁移数据，也没有改录制/导出算法。

验证：51项相关测试和TypeScript通过，包含版本兼容及原文件/会话保留。本批完整回归与构建最终结果附于本节末尾。此改动应与研究报告分开提交，便于审阅。

### 批次1：P0验收与安全升级计划

1. Windows x64实录基准与现有helper/显卡编码试编码；失败按错误详情修，不先换组件。
2. 在既有完成边界统一成片验证；故意损坏/截断/音轨缺失/时长异常做失败用例。
3. 录制前和渲染前可用空间/路径预算，区分不支持statfs与真正没有空间。
4. 依赖安全升级分批：运行时Electron/updater与构建/测试Vite/Vitest等分开，版本锁定/ABI/native重建与干净Windows包回归。未经评测不执行audit fix --force。

退出标准：同一个真实工程完成录制→编辑背景/鼠标/标注/camera→保存→重开→MP4；可取消、原素材保留、错误可诊断；安全可达性和依赖升级没有未记录阻断。Linux浏览器mock不能代替这项退出标准。

### 批次2：按参考GUI补齐已有设置

先改善分类/常用控制发现性，补golden-frame一致性和relink/恢复交互。没有后端/保存/成片支持的图形不展示成功入口。每个新类型独立序列化与两renderer分支，支持旧工程v1/v2及明确的新格式迁移策略；不让旧客户端静默降级。

退出标准：参考图中已承诺的每个控件，在当前项目矩阵标明已验证/待验证/部分/未实现，并有实际界面操作与成片证据；不是把一张参考照片的每个高级效果都声称已实现。

### 批次3：多轨与AI质量

再补完整track锁定/显示/静音、代理缓存，以及真实ASR/VAD/语义剪辑/解说配音基准。沿用现有审批/baseline/undo及本地模型顺序运行。需要新runtime时先在项目外实验，并用相同素材/相同质量证明收益。

### 批次4：高级能力单独评估

手机投屏、动画头像、3D镜头和超分模型独立任务；先核验最低硬件、Windows打包、素材/模型许可与新依赖成本，不提前下载或引入常驻GPU服务。

## 哪些可以免费、离线实现

“免费”指无需付费云API/账号，**不等于免硬件、电费、开发、签名或分发许可成本**。

- 1–16的本地工程、录制/布局/渲染/验证/恢复/性能能力可离线独立实现，复用现有FFmpeg与Windows API。硬件编码是否可用取决设备；软件回退也不要求购买API。
- 17–19可用本地FFmpeg/VAD、Whisper和现有LLM离线完成，但准确率/速度/最低内存仍须实测；模型需事先合法准备，不能把下载中的程序叫完全离线可用。
- 20的模型核验/缓存/配音可本地；新增Faiss检索也可CPU离线，但仍需合规embedding模型、索引体积预算和Windows封装。
- 不推荐为了这些能力购买常驻GPU或把原本本地流程接到付费API。真实AI头像/超分的可接受性能、许可与资源成本未验证。
