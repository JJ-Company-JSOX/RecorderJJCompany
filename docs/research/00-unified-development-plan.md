# RecorderJJCompany 统一开发建议

日期：2026-10-24。将“审计后优先修复稳定性”与“借鉴开源项目完善界面和 AI”合为一份执行顺序。[07 优先级路线图](07-feature-priority-roadmap.md)提供逐项估算与测试细节，[08 推荐执行计划](08-recommended-implementation-plan.md)提供研究统计与参考项目；本文件是两者的统一入口。

## 共同基础

沿用当前 Electron、React、TypeScript、PixiJS、FFmpeg 和原生捕获架构，复用已有录制器、工程格式、时间轴及导出器。开源研究用于选择改良方法；逐文件核实许可证后才考虑复用代码。

以[当前项目审计及功能矩阵](01-current-project-audit.md)为起点。背景、鼠标、标注、智能剪辑已有调用链，先验证和修复，不将需求列表当成全部缺失。

每项编辑能力必须经过同一条验收链：

**界面操作 → 编辑状态 → 工程保存与重开 → 素材/工程时间映射 → 预览 → 最终 MP4 → 撤销/重做。**

## 统一实施顺序

| 顺序 | 合并后的工作 | 借鉴对象与方式 | 完成依据 |
|---|---|---|---|
| 0，已完成 | 审计、四类功能矩阵、工程版本保护 | 保留已有工程实现，共享 main/renderer 版本守卫 | 修复后 1979 项测试通过、18 项跳过；生产构建通过。该结果不代表 Windows 实机验收 |
| 1，核心稳定 | Windows 实录→编辑→保存→重开→MP4；补成片健康检查、磁盘/路径预检、取消及资源回收 | OBS/ShareX/wcap 的捕获与时钟边界，Cap/OpenScreen 的验证与恢复设计 | 真实屏幕、麦克风、系统声音、摄像头素材；暂停/恢复、取消和失败后原素材保留；成片可解码、时长及音轨符合预期 |
| 2，设置与成片一致 | 按用户截图整理背景、鼠标、缩放、标注及摄像头设置；先补已有能力的断点，再增加确实缺少的类型 | 现有 Pixi 合成优先，参考 OpenScreen/Reframe 的交互及 Cap 的坐标定义；不复制未清许可证源码 | 每个可见控件能保存、重开、撤销并进入成片；多比例、裁剪、变速、排序后的关键帧与时间一致 |
| 3，编辑可靠与流畅 | 缺失素材重新定位、自动保存恢复选择、轨道状态与吸附；测量鼠标卡顿、seek、掉帧和内存，按证据决定代理预览 | Kdenlive/Shotcut 的编辑事务、间隙及代理设计，复用已有 FFmpeg | 真实工程恢复后继续导出；锁轨不被其他操作绕过；同机同片记录优化前后结果，原片和导出质量保留 |
| 4，本地 AI 质量 | 字幕识别/编辑/SRT/烧录、自适应静音与 VAD、语义剪辑及配音资源管理 | 现有 Whisper/LLM/TTS 优先；auto-editor、PySceneDetect、whisper.cpp 作为算法与质量对照 | 中文、英文、马来语真实素材；时间投影正确，审阅/取消/撤销有效；模型缺失有明确提示与主动下载入口 |
| 5，后续评估 | 手机投屏、动画头像、3D 镜头及超分辨率 | 单独核实 Windows、资源与许可证成本 | 核心流程稳定后分别定义验收，不提前用占位入口表示完成 |

每批先处理阻碍该批验收的缺陷，再补功能。可在当前 Linux 环境完成的源码检查、真实 FFmpeg 合成和自动测试继续推进；Windows 设备相关项目保持“待验证”，不以 mock 通过替代，也不因此将所有不依赖设备的工作停住。

## 安全和性能贯穿各批

- 依赖审计返回 32 个受影响包条目，包含传递依赖及开发工具链；不等于 32 次已复现攻击。Electron/updater 与构建测试工具分批评估升级，核对 native ABI 和 Windows 打包，不执行强制批量升级。
- 录制、解码、合成、编码和模型分开记录 CPU/GPU/RAM；耗时任务后台执行，有界队列、缓存、取消和错误恢复均复用现有机制。
- AI 保持本地优先、显式模型下载、资源预算和许可证检查；先复用当前运行时，新增 Python/Rust/C++ sidecar 必须有可测收益。

## 当前真实状态与交付规则

当前基线为 `codex/recording-launcher` 的审计及工程版本保护提交。10 项 Chromium 界面场景通过，使用模拟 IPC；Windows 原生捕获、多 DPI、真实模型质量及用户工程成片一致性仍待验证。详情和代码依据见[01 审计](01-current-project-audit.md)，许可证与安全边界见[05 报告](05-license-and-security-audit.md)。

每批交付均记录：实际变更、启动方式、验证命令与结果、设备/环境限制、未实现与已知问题。状态只按证据更新为“已验证、待验证、部分实现、未实现”。

本次合并仅整理建议，没有新增业务功能、升级依赖、下载模型或导入外部源码。实施时以上述顺序为准，逐项复用已有代码并完成验收。

后续执行记录：按“直接修 bug”的指示完成[导出保存与重试修复](../bugfix-export-save-2026-10-24.md)，含旧成片保护、失败后保存重试、并发/迟到结果和不支持空间查询的文件系统处理。修复后 2001 项测试通过、18 项跳过，生产构建通过；Windows 实机验收仍待完成。
