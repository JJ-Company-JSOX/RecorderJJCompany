# 四项离线组件本机验证（2026-10-19）

目标仓库 `JJ-Company-JSOX/RecorderJJCompany`，分支 `jsox-preview`。本报告只记录实际完成的本机测试，不代表真实客户视频的全面质量评估。

## 验证结果

- TypeScript、生产构建、Electron CJS 启动检查通过；改动范围内 Biome 格式与 lint 通过。
- 27 个相关测试文件、224 项测试整体通过。随后针对 VAD 边界调整的 58 项相关测试通过（含新增边界、相邻讲话、最大扩展和多音轨保护案例）。
- Edge 上 8 项界面测试通过：自动应用、取消、审阅、小窗口中英文布局、免登录本地导出、场景/转录工具，以及已有录屏优先于旧 `devOpenInput` 查询参数。
- 实际 Silero 原生侧车：12.82 秒合成英语检测到 3 段讲话，单次约 570 ms。
- 实际 PySceneDetect 隔离运行时：6 秒、三种纯色顺序切换的视频，检测边界为 0–2、2–4、4–6 秒。不是精彩片段检测，也不是逐帧精确剪切证明。
- 实际 RNNoise：独立 WAV、样本数不变、延迟补偿、取消清理与原文件校验通过；包含短于一帧及非整帧长度用例。试听和应用使用单一替换解码输入，保留原音轨身份和偏移。
- 完整打包程序的工具流程通过：场景 IPC、真实 Sherpa 转录、原音/降噪双试听、应用、保存 `.recordly`、一次 Undo、重新打开并批准派生音频、H.264/AAC 导出。导出可解码且有声，均值约 −21.5 dB；原合成媒体 SHA 未改变。

## VAD 完整自动剪辑回归

初次严格回归保留了失败记录：VAD 检出的句尾晚于原 DTW 边界几十毫秒，所有语义删除被阻止；虽然静音加速使时间线变短，实际没有删掉重复源内容。测试因此正确失败，没有把加速冒充自动删句。

修复只允许独占对应的 DTW/VAD 句段向外扩展，覆盖实际句尾；每侧最多 250 ms，保持 64 ms 声学余量，不碰其他字幕，不允许共享讲话段或大幅不一致的定位通过。多音轨 VAD 合并检查，静音编辑避开所有检出讲话前后 200 ms；缺失证据则阻止相应编辑。

修复后实际打包程序通过严格检查：

| 指标 | 结果 |
| --- | --- |
| 合成输入 | 12.820 秒 |
| 自动草稿时间线 | 10.144 秒 |
| 实际省略源内容 | 2.1635 秒，包含较早的重复句 |
| 唯一「保存并保持全屏」说明 | 完整保留 |
| 编辑器就绪 | 单次 5.256 秒 |
| 语音识别、理解和视觉分析 | 单次 CPU 84.615 秒 |
| 导出 | H.264 + AAC，音频均值 −21.8 dB |
| 音视频流时长差 | 约 23 ms |
| Undo / 保存重开 / 子进程退出 | 通过 |

此前 GUI 版同类合成测试分析约 73.329 秒、编辑器就绪约 5.389 秒。本轮分析更慢，不能宣称性能改善。这是不同轮次的单次结果，未控制后台负载，不能把差值全部归因于某个组件；也没有完成新的各进程峰值内存对比。

## 一个普通话合成样本的识别对比

本机已有中文 SAPI 语音生成 31 个汉字的短句，无麦克风录音或联网合成。忽略标点、空格，并显式归一化样本涉及的繁简字形后：

| 模型/方式 | 单次识别进程耗时 | 字符编辑距离 |
| --- | --- | --- |
| sherpa-onnx / Whisper base INT8 | 5.367 秒 | 7 / 31，漏字并将「导出」识别为「倒出」 |
| 默认 Whisper small Q5_1，含 DTW 参数 | 29.852 秒 | 0 / 31 |

两者量化与定位设置不同，只有一个合成样本，不能据此得出通用引擎优劣、真实人声准确率或纯 ASR 速度倍数。此结果支持保留 small 为默认安全剪辑识别，base 仅供可选转录对比；不能因它更快就替换默认模型。

## 交付及未验证范围

完整离线运行目录为 `release/offline-tools-test/win-unpacked`，入口 `Start-Jsox-Offline-Tools.cmd`；单独复制 `Recordly.exe` 不包含运行库和模型。完整 ZIP 为本地便携测试包，解压后可运行，无需 Vite 或现场编译。与旧恢复包和 GUI 安装包分开保存。

Windows x64、Core Ultra 7 155U、16 GB RAM、CPU 推理；本包未签名。此轮复用既有 WGC 与 CUDA 原生辅助程序二进制，其哈希和架构检查通过，但构建准备器报告部分源指纹较旧，不能称为本轮从当前原生源重编译。

尚未证明：真实录屏的持续 60 FPS、预览卡顿或 RAM 的前后改善；真实麦克风/系统音频采集；口音、噪声、轻声、长视频和马来语质量；其他硬件与全新 Windows 环境。已有无声录屏无法凭空恢复语音。建议用户录一段 15 秒带人声与操作的全屏样本，检查任务栏、鼠标和两个音频开关，再核对结果。

所有验证使用隔离测试配置和合成媒体；真实用户视频、模型、诊断原文、密钥和缓存不提交 Git。原始测试报告与失败记录留在本机忽略的 `.tmp`，不上传。既有 AGPL、FFmpeg 和 VC++ 再分发义务仍适用，测试成功不代表闭源商业分发审查完成。
