# 完整 Windows 客户端审计修复

日期：2026-10-26。基于 `669595ed`，沿用现有 Electron / React / TypeScript、bundled Ollama 与 electron-builder 配置，没有改变录制、导出或 AI 架构。

## 已修复

| 问题 | 原因 | 处理 |
|---|---|---|
| 完整客户端的内置 AI 永远起不来 | 官方 Ollama v0.40.11 运行包含有 `lib/ollama/libc++.dll`；应用启动前的路径白名单不允许 `+`，于是每次“检查本地模型”都报“缺失或损坏”。构建机校验和打包后 smoke 用的是更宽松的规则，所以都通过 | 应用与构建脚本使用同一路径规则（`BUNDLE_PATH`），并用官方 archive 的真实 75 个文件名做回归测试（`electron/ipc/autoEdit/fixtures/ollama-v0.40.11-windows-amd64-files.json`） |
| 客户端还会打一个多 GB 的 NSIS 安装包 | electron-builder 合并 `extends` 时会拼接数组，`["zip"]` 与父配置的 `["nsis"]` 合并为 `["nsis","zip"]` | 客户端与离线版（离线语音测试包继承离线版）把 `win.target` 写成字符串 `"zip"`；测试用 electron-builder 自己的配置加载器确认结果 |
| 运行包里有 2.15 GB 用不上的显卡库，且缺许可证 | 官方 archive 解压后 2.23 GB，其中 `cuda_v12`、`cuda_v13`、`vulkan` 为 NVIDIA CUDA 与 Microsoft VC++ 运行库，archive 未附它们的许可证文本 | 先按固定 SHA-256 校验完整 archive，再去掉这三个目录（锁文件 `runtime.excludedPaths`）；CPU 运行程序约 0.1 GB。按锁文件补入 LLVM（libc++、libunwind、libomp）和 mingw-w64 winpthreads 的许可证原文，放在 `licenses/` |
| 每次私有服务器启动都重新哈希全部资源 | 空闲 60 秒退出后，下次使用又完整哈希约 3.6 GB | 每次运行 App 只完整哈希一次；任何文件的大小、修改时间或变更时间改变才重新哈希。空闲 5 分钟后退出 |
| 启动中的第二个请求拿到还没就绪的端口 | 子进程一启动就记录 session，未等就绪探测 | session 在就绪探测成功后才可用；其余调用等待同一次启动 |
| 已保存的 qwen3:4b 不关“思考” | 只对 `qwen3:1.7b` 传 `think:false` | 所有 `qwen3:` 标签都传 `think:false`；其他模型不变 |
| 原声字幕铺满视频时找不到写稿入口 | “AI 配音和字幕”入口要求教程旁白时间点数量大于 0；字幕覆盖整段时为 0，故事模式随之隐藏 | Ollama 模式下始终显示入口；没有教程时间点时直接进入故事模式 |
| 录制超过 30 分钟，录前填写的要求丢失 | 要求在录制开始时保存，30 分钟后过期 | 录制期间每分钟、停止时各刷新一次；只刷新本次录制自己的要求 |
| 客户端引导客户安装 Ollama 或下载视觉模型 | 安装命令在检查前和检查失败时都会显示；画面分析警告和主进程报错提示另装视觉模型 | 新增 IPC `auto-edit-local-ai-edition`。完整客户端固定使用内置模型、不显示安装命令，错误提示改为“重新解压完整安装包”；画面警告只在模型检查后出现，并按版本给出说明；主进程报错不再推荐下载模型 |
| 旧工程缺少画面分析字段时默认开启 | 恢复时缺字段回退为 `true` | 改为 `false`；已保存的明确值照旧 |
| 识别不到原声时却提示“文字太多” | 空证据一律显示字数超限 | 区分“保留片段里没有原声”和“要求占满预算” |
| 打开视频或工程失败时没有任何提示 | 选择器返回失败但非取消时直接返回 | 抛出错误，由录制设置面板显示失败提示 |
| `npm run lint` 失败 | `captions.test.ts` 中的 `any` 和箭头表达式里的赋值 | 改为具体类型和语句块 |

## 审计报告的更正

报告中的 P2-7（“语音测试包不应要求校验 Ollama”）不成立：`electron-builder.speech.json5` 继承离线版配置，确实会打包 Ollama 资源，所以要求先校验是对的。正因为继承，离线版和两个语音测试包都会受 NSIS 体积上限影响，现在一起改为 ZIP。

## 仍需处理

- **托管**：完整 ZIP 仍可能超过 GitHub Release 单文件 2 GiB 的上限。需要决定放到对象存储或网盘，还是分卷。
- **模型清单完整锁定**：需要在能访问官方源的机器上，或用你本机已安装模型的清单，取得完整 SHA-256 并写入锁文件。
- **CPU 超时**：`/api/chat` 的 120 秒总超时等用户电脑实测后再定。
- **其他**：崩溃后残留的 ollama.exe 进程、旧 NSIS 安装版的更新提示、长录音原声缓存上限、配音不跟随片段移动，这些尚未处理。
- **真机验收**：去掉 GPU 后端后的真实 CPU 推理、完整 ZIP 构建、干净 Windows 电脑断网运行，都还没有在真实 Windows 上做过。
