# 录制整个屏幕与任务栏

选择录制源时，点击屏幕上方的 **Entire screen** 按钮，可录制该显示器的全部画面，包括 Windows 任务栏，以及录制期间切换出的其他应用。按钮也支持 Tab 聚焦后按 Enter 或空格。多显示器时，在需要录制的显示器上选择。

点击某个应用窗口会进入窗口录制，任务栏及其他窗口不属于该录制源。选择器保留这项功能；全屏按钮提供明确的另一种选择，避免最大化窗口盖住桌面后只能误选窗口。

编辑器中的自动缩放会改变回放和导出的构图，即使原视频完整，也可能暂时看不到任务栏。需要始终显示完整画面时：

1. 左侧 **Settings → Motion**，关闭 **Auto-apply fresh recording zooms（自动为新录制应用缩放）**，避免以后新录屏自动添加缩放。
2. 对已有项目，选中时间轴上的缩放块，使用 **Delete Zoom（删除缩放）**。关闭上述开关不会删除已有缩放。
3. 需要保持原视频比例时，在预览上方选择 **Native**。场景的 Padding 调整留白大小；它不会增加原录制中不存在的画面。

窗口录制已经缺失的任务栏不能靠调整预览或导出补回，需要选择 Entire screen 重新录制。原视频和项目应保留。

## 验证（2026-10-18）

选择器 UI 回归覆盖点击窗口、点击桌面、区域选择、取消，以及 HUD 的来源切换。新增三项回归模拟最大化窗口，分别通过鼠标、Enter、空格选择 Entire screen，断言提交的选择参数为 `kind: screen`、正确的 `displayId`、`record: false`，且只提交一次。

本机首轮为 22 项通过、2 项在 Vite 冷启动导航时超时；将选择器测试的总预算改为 90 秒后，两项在相同断言下独立重跑通过。该等待预算只用于测试，不属于录制或预览的性能改善。原始日志和素材保留在 Git 忽略的 `.tmp`，不随源码上传。

最终生产构建及独立的 `release/fullscreen-test/win-unpacked` 测试包已生成，CJS 启动检查、类型检查、Biome 和打包二进制检查通过。实际 unpacked 程序通过真实选择器 UI/IPC 选择了 `screen` 来源；没有在这项选择检查中启动录制。

另用本机已有、哈希通过的 WGC helper 做了三秒主显示器检查。测试自己的非聚焦合成窗口覆盖工作区，保留任务栏；输出为 H.264 **1920×1200**，工作区 **1920×1128**，底部保留区域 **72 像素**，原生日志确认精确匹配显示器 bounds，工作区三处时刻的色块验证通过。录像仅留本机 `.tmp`，没有上传或点击任务栏应用。

这只证明完整捕获范围：短样本 3.083233 秒、62 个解码视频样本，约 **20.1fps**，没有达到请求的 30fps，不能据此宣布整屏捕获已达到稳定 30/60fps；仍需更长的实际工作负载分析。测试没有采集麦克风或系统声音，也未验证编辑器导出整屏素材。沿用的 native 二进制源码 fingerprint 仍陈旧，没有声称重新编译了当前 C++ 源码。测试夹具首轮因 Windows 无边框窗口尺寸偏差在录制前停止；仅修正夹具的边框和 bounds 后完成上述检查，未改产品捕获代码。
