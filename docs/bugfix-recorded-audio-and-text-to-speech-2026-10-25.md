# 录制原声检查与可编辑文字配音

基线：`40f6f819`，`codex/recording-launcher`。复用 Electron / React / TypeScript、WGC / WASAPI、原时间轴与音频导出器；无新增依赖、模型下载或架构迁移。

## 用户问题与证据

用户确认缺少电脑播放的视频 / 音乐原声，录制前 System audio 已开启。因此不能归因于关闭开关，也不能从截图确定源音轨是否存在。Linux 工作区无法读取用户 Windows 上的录制、输出设备和音量混合器。

已检查 `useScreenRecorder` → 原生录制 IPC → WASAPI → `.system.wav` → companion discovery / approved paths → 编辑器音轨路由 / 预览同步与导出。原始 Windows MP4 可以只有画面：现有性能优化将原声保留为同名独立音轨，由编辑器和导出器合成。仅检查 MP4 是否有音频流不足以判定录音失败。

## 实际修复

- Windows loopback 初始化 / 启动失败后，画面仍能录制，但原代码没有返回系统音频失败状态。原生源码增加与 `Recording started` 同管道、有序的 `SYSTEM_AUDIO_CAPTURE_UNAVAILABLE` 标记。主进程兼容旧 helper 错误消息，并检查输出 WAV 头是否创建。无法检查繁忙文件本身不被当成捕获失败。渲染器明确提示缺少电脑声音，保留屏幕录制。
- Chromium 成功返回流但没有音轨时也会提示；此前只有 promise reject 会触发声音回退提示。
- 录制首页显示系统声音关闭的影响，以及当前默认输出设备规则。不自动改变录制偏好或电脑输出设备。
- 音频左裁剪以前只改时间轴范围，声音仍从原文件开头播放。新增可选 `sourceOffsetMs`，拖动保留源偏移，左裁剪更新偏移；波形、预览和离线音频导出使用同一偏移。预览到达原音频结尾后暂停，避免延长片段后重播开头。旧工程偏移默认为零。
- 剪刀优先拆分选中的用户音频，右半段引用后续原音频，不误切视频。拆分保留外侧淡入 / 淡出，不在切点重复它们。编辑继续使用已有撤销、重做和工程保存。

## 文字转语音与时间轴

入口：**Add Layer → Text to speech**；中文 **添加图层 → 文字转语音**。

复用本仓库 PR #22（`a1519a50`）的文字配音界面和放置方法，修正资源检查、取消后的迟到结果、视频切换时任务失效和长文本分段边界。输入文字、选择中文 / 英文和已有声音，支持试听，每段生成一个音频片段，从播放头位置放到原时间轴。再次打开即可继续添加，不需要先运行完整 AI 编辑。

使用已有 TTS 状态 / 试听 / 合成 / 取消 IPC 与离线模型。资源缺失和查询失败有说明及重新检查按钮，不自动下载。保留手动音频导入和文字标注；文字在标注属性面板修改，生成的旁白是独立音频，修改旁白内容需重新生成。

音频可移动、裁剪、拆分、调音量、静音、设置淡入淡出、删除、撤销 / 重做、保存重开，并进入原导出管线。超出视频结尾时截断并提示，不自动延长画面。沿用 Kokoro 或兼容旧声音，没有新增马来语模型。

## 本机检测

项目根目录 PowerShell：

```powershell
node scripts/diagnose-recording-audio.mjs
```

自动检查 Recordly-dev / Recordly 录制目录及其设置中的自定义目录，选最近修改的自动录制视频，不搜索整块磁盘。指定当前视频可以避免选错另一段：

```powershell
node scripts/diagnose-recording-audio.mjs "C:\path\recording-123.mp4"
```

检查嵌入音轨、同名 system / mic WAV / M4A / WebM 和已有录制诊断。复用 FFmpeg，逐个解码最多前 60 秒，区分有信号、安静样本、缺少音轨和解码错误。安静样本不代表整段无声，嵌入音频信号也不能独自证明来自系统播放。只输出本机结果，不修改媒体、工程和偏好，不联网。

## 尚未验证

用户原录制是否无信号、播放到其他输出设备、独立音轨未加载或播放被静音，需要本机检测，不能宣称原声已恢复。

Windows WGC / WASAPI 真机捕获、耳机 / 扬声器切换、多输出设备、运行中拔插和重新编译后的原生标记尚未验证。当前只捕获默认输出设备，没有新增设备选择或混合所有输出设备。用户实际模型的发音质量、延迟和试听输出也未验证；此次没有下载模型替代真机验证。

Windows “录制 → 编辑 → 配音 → 保存重开 → MP4”及长时间音画同步仍需实测。项目始终保留原始素材。

启动：已有项目依赖下运行 `npm.cmd run dev`。离线声音未安装时，可在本机运行 `npm.cmd run prepare:offline-tts`，随后 `npm.cmd run verify:offline-tts`；已安装的模型不必重复下载。
