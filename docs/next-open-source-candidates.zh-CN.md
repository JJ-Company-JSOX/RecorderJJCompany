# 下一轮值得评估的开源组件

2026-10-19 更新：四项已进入本机离线工具测试版，功能与限制见[离线工具说明](offline-tools.zh-CN.md)。旧 GUI 安装包不包含这四项；只有新 `offline-tools-test` 完整包包含。现有完整审查见[开源矩阵](../OPEN_SOURCE_AUDIT.md)。仍需更多中文实录与音质对比，不能用上游宣传速度代替本机结果。

| 优先级 | 项目 | 对本应用的价值 | 集成和验收条件 |
| --- | --- | --- | --- |
| 1 | [Silero VAD](https://github.com/snakers4/silero-vad) | 识别人声活动区间，为现有静音检测和句段剪切多加一层保护。官方提供 ONNX 和 C++ 示例；不必要求客户安装 Python。 | 先作为“禁止剪入疑似人声”的辅助证据。VAD 不理解语义，也不能证明静音画面没有价值。比较轻声、句尾、噪声、键盘声、普通话/英语样本；模型和 ONNX Runtime 需固定版本、哈希和许可证。 |
| 2 | [RNNoise](https://github.com/xiph/rnnoise) | 离线语音降噪，适合作为麦克风音轨的可选人声增强。官方提供 C 库和原始 PCM 示例。 | 必须保留原音轨、提供开关和试听，不能默认破坏音乐或系统音轨。示例要求 48kHz 单声道原始 PCM，需正确重采样并保持时间对齐。测量音质、CPU、延迟及识别是否真的改善；发布前固定独立模型资产和通知。 |
| 3 | [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) | 有离线识别、VAD 等原生接口，是未来比较中文识别或更轻运行方式的候选。官方文档包含 Windows 构建。 | 选定具体中文/多语言模型后，与现有 Whisper 比较中文错误率、时间戳、CPU 耗时、内存和安装体积。代码许可证不能代替每个权重的分发条款。没有优势就不替换，不同时常驻两个 ASR 引擎；不得向客户增加服务或命令行安装步骤。 |
| 4 | [PySceneDetect](https://github.com/Breakthrough/PySceneDetect) | 检测场景切换，为章节和候选片段提供边界。当前仓库已有云端 worker 适配器，Windows 离线版尚未包含。 | 与现有 FFmpeg 场景检测比较后再考虑引入 Python/OpenCV 分发。场景切换不等于重要内容，更不能直接决定删除；录屏里静止的操作说明也可能重要。 |

OBS Studio 可用于录制管线的对照研究：采集时间戳、队列背压、硬件编码和丢帧诊断。先测量现有 WGC 录制与预览，不能仅凭换成 OBS 代码就承诺 60FPS，也不建议把整个 OBS 引擎加入当前轻量编辑器。

最值得优先做的用户功能是**文字驱动剪辑**：点击转录句子预览相应源片段；删除句子时预览并同步调整现有时间线；保留 Undo、重排素材和 `.recordly` 兼容性。它可基于当前字幕和源时间映射实现，不需要另换编辑器，也不能在句段级定位尚不可靠时宣称逐字精准剪切。

每一项都应满足：无需客户配置、完全离线、可取消并释放资源、保留原始文件、实际导出音画同步、许可证/模型固定来源。四项按需运行；默认自动剪辑仍保留原有 Whisper small 与语义模型流程，新增较小识别模型用于可选对比。
