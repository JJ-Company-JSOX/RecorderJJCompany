## 已实施

保留 #22 的自动应用/审阅/撤销交互，在同一编辑器内提供三档，并在电脑上记住用户选择：

| 模式 | 实际执行 | 资源与功能边界 |
|---|---|---|
| 快速剪辑，首次默认 | 原有媒体检测与规则计划，使用录制点击、静音/静止画面和原有保护规则 | 不加载视觉/语言模型、不调用 ASR，不声称生成新语音字幕或理解重复语句 |
| 快速剪辑＋字幕 | 媒体检测、原有 Whisper/VAD 对齐、字幕与有依据的停顿建议 | 无视觉大模型和语义推理；识别仍有 CPU 成本，不承诺实时 |
| 完整 AI 分析 | 原有媒体检测、语音、语义和视觉分析 | 保留原能力、模型与内存门槛；耗时更长 |

主进程 `auto-edit-complete` 增加可选 `mode: "speech" | "full"`；省略时保持旧完整行为，未知模式在分析前拒绝。语音档在转录和 VAD 保护后直接返回，未创建大型 AI session。素材审批、取消、任务所有权、状态基线和迟到结果防护继续复用。

所有模式仍进入原 `buildEditPlan` / `addSpeechSuggestions` / `applyEditPlan`、history、工程保存与字幕导出链。快速模式的已有字幕保护规则保留；字幕档使用源时间字幕，继续走工程→时间轴投影。没有创建另一套剪辑或导出管线。

“不新增缩放”设置现也作用于规则模式；无音频回退时保持用户选择，不擅自开启缩放，也不在字幕档悄悄升级为视觉推理。

媒体检测方面，只有一个内嵌音轨时，在同一 FFmpeg 读取过程中检测视频冻结和音频静音。多内嵌音轨和外置伴随音轨继续逐轨验证并取静音交集。保留原分辨率、全部帧、阈值、边界 padding 和音频对齐保护，未用降采样代替安全的画面检测。

## 实际小基准

Linux 本环境、相同 FFmpeg、20 秒 1920×1080/24 FPS H.264＋AAC 合成移动素材；同一程序依次交替执行 `before, after, after, before, before, after`。运行基准时未同时执行构建/测试。

| 媒体检测 | 三次实际墙钟耗时（ms） | 中位数（ms） |
|---|---|---|
| 修改前 | 778 / 769 / 942 | 778 |
| 修改后 | 661 / 705 / 677 | 677 |

本次中位数减少约 **13%**，三次修改前后返回的 evidence JSON 完全一致。这只测量媒体检测，样本量小；不能外推为 Windows 整体 AI 加速倍数、RAM 峰值改善或所有编码格式的性能保证。

临时基准脚本、两版打包模块、素材和结果位于 `/tmp/recordly-fast-benchmark/`，不提交视频或编译模块。核心改善还包括快速路径不执行重模型阶段；本环境未实际运行 Windows 模型，因此不提供虚构的端到端倍率。

## 使用和后续

在项目目录停止旧开发程序后更新并运行：

```powershell
git pull --ff-only origin jsox-preview
if ($LASTEXITCODE -eq 0) { npm.cmd run dev }
```

先选择“快速剪辑”；需要字幕时选“快速剪辑＋字幕”；需要语义去重或画面理解时选“完整 AI 分析”。不需要重新安装依赖或模型。

下一轮需在目标 Windows 电脑记录冷启动、预览 FPS、p95 seek、AI 各阶段耗时及进程峰值内存，再决定代理预览/缓存预算。本批不声称已修好所有播放卡顿或安装耗时。
