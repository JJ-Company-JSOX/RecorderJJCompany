## 完成内容

### 工程与草稿

新增可选的 `storyWorkspace`（内部 version 1），纳入现有工程快照、自动保存、脏状态检查与撤销/重做。保存主题、受众、事实卖点、结尾目标、素材说明、字幕参考开关、故事模式、解说语言/风格、未提交故事稿、逐句修改、标题、时间段、校验基准和已生成配音的文案快照。旧工程无需迁移即可打开。只接受已知且有容量限制的字段，非法草稿/绑定不会被当作可信全局数据。

重新打开故事工程会恢复故事任务界面，不自动加载模型或发起推理；需要重新审阅确认后才能加入声音或文字。解说面板提供直接返回检查/更换 Ollama 模型的入口，不丢失当前草稿。保存的配音语言单独显示，避免把旧英文稿误认为会按当前界面语言重新配音。比较基准不再受 JSON 字段顺序影响。

### 主动开启的原声字幕参考

“用已有原声字幕帮助策划故事”默认关闭。开启后，把已有原声字幕映射到当前保留片段的工程时间，正确处理剪切、重排、变速、重复素材及绑定字幕；排除生成的解说字幕和画面间隙。部分裁掉且缺少逐字时间的字幕会略过，避免把被删掉的话重新提供给 AI。有逐字时间时，只采用完全保留的词。

界面显示实际采用/略过数量，并提供进入既有字幕面板的按钮。不会悄悄启动 ASR、安装模型或把原始音频交给 Ollama。后台明确把这些内容标记为“不可信的已有编辑字幕”，不能冒充听取了原声。

为照顾 8192 上下文的本地小模型与 RAM：无画面时参考文字合计最多 4000 字符，有抽样画面时最多 2000 字符；字幕最多 80 段/3000 字符，并且仍受合计预算限制。界面披露当前文字量与被省略的字幕。这是保守字符保护值，不是精确 token 计数或模型性能保证。

### 配音重试与取消

同一编辑会话使用最多 64 项的配音缓存，按文字、语言和声音区分。仅调整场景时间可复用成功生成的 WAV；修改一句只生成缺失的新句子。缓存不覆盖原素材，不改变配音速度，也不把超时配音悄悄挪到另一个画面。界面显示已有语音实际长度和画面可用长度，方便修复超长句子。等待估算按缺失文案的工作量区分。

已加入的旧配音会保留；文案、声音或时段变更后显示可能不匹配的提示。配音快照随工程保存；会话缓存不保证重开工程后直接复用，现有音轨本身始终保留。

原生 TTS 返回后、WAV 写入前后及试听结束后检查取消。取消的结果不能晚到后加入工程；写入期间取消只清理刚生成的文件，保持 AbortError。原生引擎仍不能立即中断正在生成的句子，其 CPU 任务可能需要等当前句结束。

### 重复素材的字幕与导出

审计发现故事字幕过去只有源时间：同一源画面重复出现时，会重复显示其他段的解说，或把第二段字幕当成冲突丢弃。

新增可选 `CaptionCue.clipId` 与显式片段祖先 `ClipRegion.parentClipIds`，绑定字幕跟随对应片段的拆分和自动裁剪后代；普通原声字幕保持源素材范围的既有行为。跨切点字幕分片映射，保留尾部。

中央预览按当前片段匹配字幕。新增共享 `captionRenderConfig`，在已有 MP4/GIF/缩略图路径将字幕和逐词时间投影到工程时间；两套既有渲染器通过明确的坐标标记选字幕时钟，保留旧的源时间调用方式。摄像头、鼠标及源视频时钟未改。原生静态导出遇到字幕继续使用既有回退逻辑，不另建导出器。
