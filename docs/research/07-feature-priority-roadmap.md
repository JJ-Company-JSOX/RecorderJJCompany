# 07 — 分阶段路线图与20项优先工作

统一执行顺序见[合并开发建议](00-unified-development-plan.md)；本报告保留各项工作量、风险及验收细节。

日期：2026-10-24。估算为一名熟悉仓库的工程师的净开发/测试时间，不含等待设备、签名、许可澄清。风险和资源影响是工程判断，未测量不写性能收益百分比。A=保留、B=改良、C=独立新增、E=当前不引。没有足够证据支持D整组件替换。

## P0 — 数据、稳定和安全先行

### 1. A-01 工程版本拒绝保护（B，已实施）
- 目标：旧客户端拒绝未来/无效版本，保留v1/v2；参考Cap恢复边界与现有Project模型，不复制源码。
- 工作量：0.5–1天；技术风险低；性能O(1)；无新许可依赖。
- 验收：version999/-1/1.5不进入审批/会话，原JSON/媒体字节不变；1/2仍可打开。测试：51项相关测试已通过，完整构建/全量结果见08。

### 2. Windows录制—编辑—重开—导出基准（B）
- 目标：固定10–30秒含多位置点击/旁白/系统声音/camera素材；参考OBS/ShareX/wcap的故障及clock边界。
- 工作量：2–4天；风险高（真实驱动/DPI/时间）；不增运行时，无新增源码许可。
- 验收：两屏不同DPI、屏幕/窗口、暂停/恢复、摄像头失败均保留录屏；导出字幕/鼠标/音画偏差按产品明确容差验收；测试：Windows x64录屏→项目→MP4证据、FFprobe和人工视听，并记设备/版本。

### 3. 统一成片健康验证（B）
- 目标：在现有导出完成边界统一容器、视频可解码、预期音轨和时长检查；参考Cap `validate_instant_recording`。
- 工作量：3–5天；风险中（长片解码成本/误拒绝）；CPU/磁盘I/O增加，可用头尾探测和有界全解码策略；Cap目录AGPL/MIT需逐文件，建议独立实现。
- 验收：正常、无声、损坏/截断、时长异常、混合采样率/帧率，明确取消和失败重试；不另起渲染管线。

### 4. 录制前/渲染前磁盘与路径预检（B）
- 目标：现有最终保存检查外，补录制目录和temp/output卷预算；参考OpenScreen diskSpaceCheck。
- 工作量：1–3天；风险中（网络盘statfs不支持）；轻量I/O；MIT设计参考，复制需保留notice。
- 验收：低空间、目录删除、权限拒绝、跨卷保存、statfs失败均可理解且不覆盖原片。测试注入空间/权限失败＋真实小文件，不能仅断言函数调用。

### 5. 取消/窗口关闭/设备掉线的资源回收（B）
- 目标：所有owned child/stream/AudioContext/GPU队列和temp统一终止；参考OBS设备重建、Cap crash sentinel、Screenity offscreen状态。
- 工作量：3–5天；风险高（late reply/句柄竞态）；减少泄漏但收益需测；不引上述框架。
- 验收：转录、摄像头准备、导出写入时取消/关闭，原素材保留，无后续自动应用；测试进程退出、文件句柄和late result，不使用假进度。

**P0安全发布门槛（横跨以上工作，不额外计作功能）：** 05的npm audit返回32受影响包条目；Electron等生产运行时与Vite/Vitest开发工具分开评估升级。不能自动force升级。每批需锁文件diff、native rebuild/打包验证；没有可用Windows机器时不宣称发布可用。

## P1 — 高价值、低重复建设

### 6. 参数快照与预览/成片golden frame（B）
- 目标：背景/圆角/阴影/blur/crop/鼠标/camera/标注同一snapshot；参考现有renderers和Cap布局。
- 工作量：3–6天；风险中；只测试增加渲染开销；无新增素材许可。
- 验收：三种比例、不同padding、加速/排序后的关键帧图像差异可解释，SRT与burn-in同时间。测试实际合成图像及MP4，不只比较config对象。

### 7. 缺失素材重新定位（C）
- 目标：缺失主视频/camera/audio/background时逐项定位，记录旧→新映射后显式保存；参考ScreenToGif/现有资源审批。
- 工作量：3–5天；风险中高（错误素材/权限）；小I/O；仅参考设计。
- 验收：取消不改工程；错误类型/尺寸/时长有提示；新路径审批，旧路径不越权；重开后正确播放/导出。

### 8. 异常退出恢复选择（C）
- 目标：利用已有atomic backup/autosave，不新建第二project store；参考Cap sentinel。
- 工作量：3–5天；风险中；少量元数据I/O；AGPL目录复用需注意，建议独立。
- 验收：正常关闭不误提示、断电/损坏JSON有候选、恢复前保留两代、拒绝未来版本；测试在临时用户目录模拟进程结束，不破坏用户工程。

### 9. 编辑器设置分类与发现性（B）
- 目标：按用户FocuSee照片整理Scene/Cursor/Annotations/Webcam/Audio/Captions/AI；已有控件保留功能，不把未实现特效摆出来；参考Reframe UX（不复制未清license代码）。
- 工作量：2–4天；风险低中；不增模型/框架；自制图标/允许许可素材。
- 验收：中文小屏可滚动、常用开关无需Advanced、所有可见按钮有行为，保存重开后值不丢；测试keyboard/pointer/undo与最终export。

### 10. 预览/队列/内存性能测量（B）
- 目标：定位用户“鼠标卡/占RAM”，记录decode/render/seek/encode/RAM，而非笼统压缩ZIP；参考Cap memory profiling和现有metrics。
- 工作量：2–4天；风险低；轻量可关闭指标；无新增许可依赖。
- 验收：同机器同片同预设有before/after，记录p95 seek、FPS/掉帧及峰值。没有测量不得宣称优化成功。

## P2 — 专业录屏增强

### 11. DPI与鼠标去重（B）
- 目标：统一物理屏幕→录制区域归一化→canvas；依据Cap normalize与wcap cursor hide。
- 工作量：3–6天；风险高；事件采样CPU小，纹理重绘需测；Cap/scap目录许可逐项。
- 验收：负坐标显示器/125%/150%/200%/移动窗口；不同时录入系统cursor又重绘；重开工程/export一致。

### 12. Zoom编辑可解释性与边界（B）
- 目标：保留现有聚类，集中gap/距离/倍率/过渡参数，展示候选原因；参考Reframe算法但独立实现。
- 工作量：2–4天；风险中；CPU线性或近线性；未清许可不复制源码。
- 验收：相邻远点击不合并、近点击不抖动、不露空白、手工新增移动删除及undo；测试真实cursor fixture与导出关键帧。

### 13. 摄像头布局/偏移/失效恢复（B）
- 目标：现有独立素材支持布局/镜像/圆角/同步可见性；参考BetterCapture写入层分离。
- 工作量：3–5天；风险高（设备）；多一解码器/纹理，需预算；MIT只学职责也可。
- 验收：不同设备FPS、暂停/恢复、负/正offset、源丢失，屏幕仍可编辑；UI重开与成片视听验证。

### 14. 新标注类型（C）
- 目标：先矩形/圆形，再有明确需求的spotlight；与text/arrow/blur同一union、save/renderer/history；不是新网页overlay。
- 工作量：4–8天；风险中；blur/spotlight可能额外pass；使用自制图形。
- 验收：在裁剪/变速/排序/画布比例后位置和时间一致，新增类型旧工程可读，新工程旧客户端拒绝；真实导出和undo测试。

### 15. 完整轨道状态与吸附（C）
- 目标：track lock/mute/visibility进入命令层、保存和导出；参考Kdenlive/Shotcut。
- 工作量：5–10天；风险高；元数据开销小，混音/解码取决可见轨道；不引MLT/C++引擎。
- 验收：锁轨不能keyboard/拖拽/ripple绕过，静音不删素材，隐藏在export生效；多片段+camera/subtitle关联边界测试。

### 16. 可选代理预览与有界缓存（B）
- 目标：仅性能测量证明必要时，为4K长片提供低清代理；参考Kdenlive/Shotcut。
- 工作量：5–8天；风险中高；用CPU换预览流畅，增加磁盘；复用FFmpeg。
- 验收：原始视频不改，最终export用原片，代理失效/清理不删引用素材；磁盘与seek基准对照。

## P3 — AI视频编辑增强

### 17. 自适应静音与VAD联合（B）
- 目标：现有规则基础上对比相对响度/呼吸padding；参考auto-editor和Better Shot。
- 工作量：3–5天；风险高（误切语音）；有界音频解码CPU；算法独立实现，引用许可按文件。
- 验收：轻声/音乐/噪声/全静音/多音轨，不能把有人声的静态画面剪掉；人工标注小基准+审批/undo。

### 18. 字幕识别/编辑/样式质量（B）
- 目标：复用Whisper本地ASR和source→timeline投影，语言选择、拆合、SRT、烧录对齐；faster-whisper仅对照。
- 工作量：4–7天；风险中高；单一ASR驻留避免加倍RAM；代码/模型voice分别许可。
- 验收：中文/英文/马来语真实音频含数字/否定、变速/排序/重复片段；字幕保留/断词和SRT时间可解码核对。

### 19. 语义剪辑/按文字删除的可信度（B）
- 目标：保留baseline/conflict/VAD保护和用户审阅；参考现有speechPlan/llama，而不是LLM直接写FFmpeg命令。
- 工作量：5–10天；风险高；本地模型CPU/RAM现有预算；不要求云API。
- 验收：保留唯一信息/数字/否定，重复take有依据，uncertain不默认剪；取消/stale plan/一键undo，真实数据人工评审。

### 20. 离线模型/配音/检索资源契约（B/C）
- 目标：固定下载revision/hash、可取消与重试、voice许可和缓存；未来SearchAdapter再用Faiss，不改Firebase。
- 工作量：5–10天；风险中高（模型/包体）；不常驻第二runtime，embedding/索引RAM另预算；所有voice/model分别审核。
- 验收：缺失/损坏模型不假成功，离线启动不下载，识别结果可复用且source hash隔离；合成语音先审批，索引结果可追溯时间与工程。

## P4 — 暂缓的高级能力

手机投屏、AI动画头像、3D镜头、Real-ESRGAN超分辨率、复杂烟花/节日效果独立评估，不算进当前20项核心优先工作。必须另给设备/驱动/模型许可/包体/CPU-GPU-RAM/取消/保存和成片验收，不能先挂按钮或预设必须买GPU服务。
